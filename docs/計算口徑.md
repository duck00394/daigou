# 計算口徑

所有金額以整數「元／円」計算，不使用浮點數累加。匯率以「微單位」整數保存（1 JPY = rateMicro ÷ 1,000,000 TWD），換算一律四捨五入到元。分攤使用最大餘數法，分攤結果總和恰好等於原金額。

程式位置：`src/server/calc/order.ts`（訂單金額與狀態）、`src/server/services/inventory.ts`（庫存）、`src/server/services/reports.ts`（統計與報表）、`src/server/services/purchase.ts`（成本分攤）。對應測試在 `tests/unit` 與 `tests/integration`。

## 數量

| 名稱 | 公式 |
|---|---|
| 有效件數（明細） | 訂購數量 − 已取消數量 |
| 待出貨（明細） | 有效件數 − 已出貨 |
| 已到貨（明細） | 已保留 + 已出貨 |
| 有效訂購件數（分類、商品） | 已確認訂單中各明細有效件數的總和；待確認訂單不計入 |
| 已取消件數 | 所有取消紀錄的數量總和（含已取消訂單） |
| 有效購買人數 | 有效件數 > 0 的明細中，不同買家 ID 的數量。同一買家重複購買、追加只算 1 人 |
| 分類統計 | 依訂單明細的「銷售歸屬分類」計算，每件只歸屬一個分類，各分類可直接相加，不會因商品同時屬於多個活動而重複 |

分類統計中的待下單／待到貨／待出貨／已出貨會把有效件數完整拆開：

- 已出貨 = min(已出貨, 有效件數)
- 待出貨 = min(已保留, 有效件數 − 已出貨)
- 剩下的數量：明細採購狀態為「已向供應商下單」→ 待到貨，否則 → 待下單

### 銷售歸屬分類的自動判斷
1. 建單時有指定 → 使用指定值（必須是商品所屬的分類）
2. 訂單屬於代購團，且代購團的主要分類是商品所屬分類之一 → 使用該分類
3. 商品只屬於一個分類 → 使用該分類
4. 否則為「未歸類」，可在訂單明細上手動指定

## 庫存

| 名稱 | 公式 |
|---|---|
| 實際在庫 | Σ 在庫變動（到貨 +、盤點 ±、出貨 −） |
| 已保留 | Σ 保留變動（保留 +、取消保留 −、出貨 −） |
| 可用庫存 | 實際在庫 − 已保留 |
| 待到貨 | Σ（採購數量 − 採購取消數量 − 已到貨數量），不含草稿與已取消的批次 |
| 有效預購（未出貨需求） | Σ max(0, 有效件數 − 已出貨) |
| 已出貨（已售出） | Σ 出貨流水數量 |
| 未分配需求 | Σ max(0, 有效件數 − 已出貨 − 已保留) |
| 缺貨 | max(0, 未分配需求 − max(0, 可用庫存) − 待到貨) |

規則：
- 庫存只能透過流水異動，不直接修改數量。每筆流水記錄時間、原因、關聯訂單明細與來源採購明細。
- 保留不會超過明細「尚未保留、尚未出貨」的需求，也不會超過可用庫存。
- 出貨一律從該明細的保留中扣除（同時扣在庫與保留），出貨量不能超過有效件數 − 已出貨。
- 取消數量後，若保留量超過剩餘需求，多出的部分自動釋放回可用庫存。已出貨的數量不能取消。
- 到貨、出貨、付款、退款、手動建單、匯入都帶有一次性識別碼並以資料庫唯一性限制防止重複提交；同一商品或訂單的異動以列鎖序列化。

## 訂單金額

| 名稱 | 公式 |
|---|---|
| 明細毛額 | 成交單價 × 有效件數 |
| 明細折扣（生效） | 有取消時：round(明細折扣 × 有效件數 ÷ 訂購數量) |
| 明細淨額 | 明細毛額 − 明細折扣（生效） |
| 整單折扣（生效） | round(整單折扣 × 剩餘商品淨額 ÷ 原始商品淨額)；全部取消時為 0 |
| 運費（生效） | 仍有有效商品時全額保留；全部取消時為 0（需減免運費時直接修改運費，會留下紀錄） |
| 應收 | max(0, Σ 明細淨額 − 整單折扣（生效） + 運費（生效）) |
| 已收 | Σ 未作廢的付款 |
| 已退款 | Σ 狀態為「已退款」的退款（待退款不計入） |
| 退款處理中 | Σ 狀態為「待退款」的退款 |
| 淨收 | 已收 − 已退款 |
| 待收 | max(0, 應收 − 淨收) |
| 應退 | max(0, 淨收 − 應收) |
| 尚未建立退款的應退 | max(0, 應退 − 退款處理中) |

- 退款建立時，待退＋已退的總額不可超過已收。
- 登記錯誤的付款用「作廢」，保留原紀錄、不計入已收。
- 訂單上的 *Cache 欄位只是列表用的快取，每次異動後在同一交易中依流水重算。

## 營收、成本與利潤

| 名稱 | 公式 |
|---|---|
| 明細營收 | 明細淨額 − 分攤到該明細的整單折扣（最大餘數法） |
| 已實現營收（截至某時點） | Σ round(明細營收 × 已出貨 ÷ 有效件數) + round(運費 × 已出貨件數 ÷ 有效件數) |
| 某月已實現營收 | 截至月底的已實現營收 − 截至月初的已實現營收（依出貨單的出貨時間） |
| 採購品項商品金額 | 單價 × 有效件數；幣別為日幣時 × 採購團鎖定匯率（四捨五入到元）。單價優先用「實際單價」，未填時用「預估單價」 |
| 採購品項實際總成本 | 商品金額 + Σ 分攤到該品項的共同費用（代購費、日本／台灣國內運費、國際運費、關稅等） |
| 銷貨成本（每筆出貨流水） | 來自採購批次：round(實際總成本 × 出貨件數 ÷ 採購件數)；手動入庫：入庫成本快照 × 件數；都沒有：建單時預估成本 × 件數（報表會顯示以預估成本計算的件數） |
| 某月銷貨成本 | Σ 該月出貨流水的銷貨成本 |
| 其他費用 | 不屬於採購批次的費用（設定頁登記），依費用日期歸月 |
| 已實現利潤 | 已實現營收 − 銷貨成本 − 其他費用 |
| 預估未實現利潤 | 已確認且未完成訂單：（應收 − 已實現營收） − Σ 未出貨件數 × 預估成本 |
| 本月新訂單金額 | 訂單日期在本月、已確認訂單的應收總和（與營收分開） |
| 本月收款／退款 | 付款日期在本月的未作廢付款；完成日期在本月的已退款 |

- 收到的錢（現金）不等於營收，也不等於利潤，三者分開顯示。
- 已取消的數量不計入營收；取消前已收的款項在退款前列為「應退」。
- 採購團費用（運費、代購費、關稅等）預設「不攤，單獨記」（method = NONE）：算進這團總額與「還要付」，不進商品成本，並以登記日期算進當月「其他費用」。誰付的：預設跟著這團的歸屬（個人團＝主人、合資團＝依付款比例）；可指定某位經營者，或「兩人一起付」並填每人金額（合計須等於費用台幣金額）。只有兩人一起付時，介面才提供攤進商品成本的選項。
- 商品名稱＝活動＋角色＋種類（＋規格），例：ANA兔兔 吊娃。有活動時，商品識別（variantKey）包含活動，不同活動是不同商品；舊格式商品（沒有活動、規格填活動名，或只在這個活動買過）會被沿用，不會拆成兩個商品。舊名稱只有在活動頁按「改成新格式」才會改，只改顯示名稱。
- 共同費用（日本國內運費、國際運費、關稅、包材、平台手續費等）可依件數、重量、商品金額或手動分配到批次明細。每次費用或明細變動時整批重新分攤，每筆費用的分攤合計恰好等於費用金額，不會重複或遺漏。日幣費用以批次匯率換算。
- 預估成本：建單時優先使用商品的「預估成本」，沒有時以日幣官方價 × 當時預設匯率計算，並保存匯率快照。之後修改預設匯率不會改變既有訂單或批次。

## 採購團與批次新增

- 價格分成五種，各自保存：商品參考售價（商品主檔）、採購預估單價、採購實際單價、對客售價（每個採購團各自一份）、共同費用分攤。
- 商品 = 系列 × 商品類型 × 角色 × 規格。同角色不同規格或類型是不同商品 ID。
- 批次新增只建立採購品項，不增加庫存；只有「登記到貨」會增加實際在庫。
- 新商品第一次建立時，才會用該列的單價（日幣）與對客售價帶入商品主檔；之後不會改寫主檔，也不會改寫其他採購團。
- 參考帶入順序：同供應商最近一次採購 → 任何採購團最近一次 → 商品主檔 → 空白。
- 採購品項最少數量 = 已到貨數量 + max(0, 已向供應商下單且尚未保留、出貨的買家需求 − 其他採購團的在途數量 − 目前可用庫存)。修改或刪除低於這個數量會被拒絕；批次修改時任何一列不合法，整批都不寫入。
- 批次新增每一列各自一個交易，列識別碼 = 送出識別碼 + 列代碼；重送時已成功的列回報「先前已建立」，不會重複新增。

## 經營者責任紀錄與經營者對帳

四種角色彼此獨立，不可混用：

| 角色 | 記在哪裡 | 說明 |
|---|---|---|
| 買家（客人） | 訂單 `Order.buyerId` | 向我們預訂商品的人；付給我們的錢記在「收款」`Payment` |
| 訂購負責人 | 採購團 `PurchaseBatch.orderedById` | 經營者中負責向官方或代購下單的人 |
| 主要付款負責人 | 採購團 `PurchaseBatch.paymentResponsibleById` | 負責安排付款的人（不一定是實際付錢的人） |
| 收貨負責人 | 採購團 `PurchaseBatch.receivingResponsibleById` | 主要負責清點的人 |
| 實際付款人 | 每筆供應商付款 `SupplierPayment.paidById` | 真正付出那筆款項的人；同一團可多筆、多人 |
| 收貨確認人 | 每次收貨 `ReceivingRecord.receivedById`（必填） | 實際清點那一次到貨的人 |

- 經營者以固定 id 關聯；改名只改顯示，歷史紀錄不會換人。可選「未指定」（存為空值）。停用的經營者不能被新指定，但既有紀錄保留。
- 供應商付款：
  - 已付款（PAID）才計入「實際支付」；待付款（PENDING）另列，不計入；已作廢（VOIDED）保留紀錄但不計入。
  - 不同幣別分開加總，永遠不把日幣與台幣直接相加。
  - 換算台幣只用該筆付款自己填的「實際匯率」：`台幣 = 四捨五入(日幣 × 實際匯率)`；沒填匯率的日幣付款不換算，只顯示原幣並註明筆數。採購團鎖定匯率是成本估算用，不拿來換算付款。
  - 防重複：每次送出帶一次性識別碼（`dedupeKey` 唯一）；同一團相同「交易參考編號」的有效付款會被擋下。
  - 修改、作廢都寫入稽核紀錄（修改前後值與原因），作廢必須填原因，作廢後不能再修改。
- 收貨清點：每次到貨一筆紀錄，每個品項記「實收、瑕疵、缺少」。只有 `實收 − 瑕疵` 的良品入庫（`InventoryMovement.receivingLineId` 連回這次收貨），缺少只做記錄。良品不能超過該品項尚未到貨的數量。「庫存 → 到貨登記」選擇採購團來源時，同樣建立收貨紀錄並要求收貨確認人。
- 經營者對帳頁的日期篩選：採購團依下單日（不含已取消）、付款依付款日、收貨依收貨日。
- **不推算**合夥人之間的成本分攤、墊款或誰該還誰：「誰付給供應商的錢」不等於「誰應負擔的成本」。若日後需要內部結算，需另訂規則。

## 砍單、跨團複製、自留與活動總覽

- **砍單**：在採購品項上點「砍單」，選擇原因（代購砍單／賣家取消／商品缺貨／自己取消／其他，「其他」須補充文字）。
  - 只取消該品項的指定數量，已到貨的不能砍，同團其他品項不受影響。
  - `cancelledQty` 增加，並記錄 `cancelReason` 和稽核紀錄；費用會重新分攤。
  - 砍掉的數量不計入有效採購、待到貨或成本。
  - 已付給供應商的款項不會被當成已退款，畫面會提醒。
  - 因此不夠貨的買家明細（從最晚下單的開始算）會被列出；勾選後標為「缺貨」並留下事件紀錄，不會刪除訂單。
  - 「刪除」只用於輸入錯誤、完全沒有到貨或依賴關係的品項。
- **跨團複製品項**：只建立新的採購品項（商品與規格）。
  - 舊價格只是參考值，以黃底標示，必須勾選確認後才能新增。
  - 付款、收貨、退款、出貨、庫存與費用都不會複製。
  - 以送出識別碼防止重複新增。
- **自留**：以 `KEEP` 庫存異動把良品從可售庫存移出（在庫 −n），並保留採購批次來源，改回出售則 +n。
  - 已保留給買家的數量不能自留。
  - 可售 ＝ 實際在庫 − 已保留給買家，自留的已不在其中。
- **活動總覽**：採購團以 `PurchaseBatch.categoryId` 歸屬到活動／系列。
  - 活動頁列出各團進度、成本（標註暫估）、已付與待付款（依幣別），以及異常（砍單、瑕疵、缺少、逾期、尚未付款）。
  - 跨團價格比較：每個商品一列、每團一欄。日幣依各團鎖定匯率換算台幣。
  - 可在「商品單價」和「含費用單件成本」之間切換；實際單價未確認或該團尚未登記費用時標「暫估」。

## 現貨直接出售

- 沿用既有的訂單、出貨、收款與庫存流水，不另建庫存或帳務系統。一次操作會：
  - 建立來源為「現貨出售」（`OrderSource.QUICK`）的訂單；沒填買家就記在固定的「散客」，填了名稱則依名稱或別名找既有買家，找不到才新增。
  - 立即出貨：只從可售庫存保留後出貨，已保留給其他買家的、自留的都不會被動到。
  - 依選擇登記已收款。
- 收入依出貨認列，成本取自 SHIP 流水所屬的採購批次（含分攤費用），和「成本與利潤」報表同一套口徑，不會重複計算。批次的實際單價或費用尚未確認時標為暫估。
- 作廢：
  - 建立一張負數出貨（退回），日期記在原出售日；SHIP 流水依原批次以正數退回，讓原月份的收入與成本一起歸零。
  - 取消明細、作廢自動登記的收款，訂單標為已取消。原紀錄全部保留。
  - 只有「現貨出售」能用這個作廢，一般訂單仍在訂單頁處理。
- 更正：同一交易內先作廢舊紀錄（商品先退回），再依新內容建立一筆。
- 重複送出：以送出識別碼防止重複建立訂單、出貨與收款。

## 庫存估值與平均成本

- 每個成本批次的單件成本 = 該採購品項的完整成本（商品金額依該團鎖定匯率換算台幣＋分攤費用）÷ 有效數量。手動入庫以填寫的成本加權平均。
- 估值以整數比例計算（`mulDiv`，四捨五入），和出貨時的銷貨成本使用同一套口徑，所以「已賣出成本＋剩餘庫存估值＝全部購入成本」。
- 可售、已保留、自留分開估值。平均成本＝目前持有（在庫＋自留）的加權平均，只是參考；實際出售成本依先進先出的批次計算。
- 批次的實際單價還沒確認，或該團還沒登記任何共同費用時，估值與成本都標「暫估」。

## 資料健康檢查（設定頁）

- 唯讀檢查：依流水重新核對以下項目，只回報、不修改：
  - 每個成本批次的在庫、保留、自留都不能為負，保留不能超過在庫。
  - 到貨不超過有效採購數量，收貨紀錄的良品與入庫流水一致。
  - 採購團狀態與到貨一致。
  - 共同費用分攤合計等於費用金額。
  - 出貨數量與扣庫一致。
  - 訂單金額、數量快取與重算結果一致。
- 「重算狀態與金額快取」只依原始紀錄重算採購團狀態與訂單快取，不改動庫存流水、付款或訂單內容。
- 自動化測試在每一項整合測試結束後都會執行同一套檢查。

## 防重複送出

- 有一次性識別碼的操作（建單、收款、退款、出貨、到貨、收貨、供應商付款、自留、批次新增、跨團複製、現貨出售）：重送只會執行一次。
- 會累加的操作（採購砍單、買家訂單取消一件、追加商品、新增共同費用、新增其他費用）：送出時登記一次性識別碼（`RequestKey`）。同一碼只會成功一次；同時送出時第二個會等第一個完成再判定為重複；失敗的請求不佔用識別碼，可以直接重試。

## 商品搜尋

以空白分開的每個關鍵字都要符合，順序不拘，可以出現在名稱、編號、別名、系列、角色、類型或規格。例：「吊娃 小八」。

## 各自採買與合資

- 每個採購團都有一個歸屬，就是「這團是誰的」：
  - 個人：歸某一位經營者（`orderedById`，原本的「訂購負責人」已合併進來）。
  - 合資：沒有單一主人（`ownership = JOINT`）。
- 每一件庫存都記得是從哪一團進來的，所以庫存、出售、自留都依那一團的歸屬分人。
- 合資團：
  - 件數列在「合資」，不拆成半件。
  - 賣掉的錢（收入、成本、毛利）依各自實際付給代購的已付款台幣金額比例分，也就是「誰付錢誰拿錢」。日幣以該筆實際匯率換算，沒填就用該團匯率。分配用最大餘數法，合計不變。
  - 還沒登記付款時不分，顯示「合資（還沒登記付款）」。
- 出售、自留可以選「賣誰的／留誰的」：
  - 只會依先進先出扣那個人的成本批次。
  - 預設是「這支手機是誰在用」的那個人，記在裝置 Cookie，可以在設定頁更改；那個人沒有可賣的庫存時，改選第一個有庫存的。
- 不推算兩人之間誰欠誰。
- 活動頁與活動總表會顯示：總額、每一團的總額、每個人買了多少（合資依付款比例分）、依進度分的金額，以及這個活動進來的庫存依歸屬分開的數量。

## 採購團進度（口語）

- 可以自己點選的進度：已請代購 → 代購收到了，等寄出 → 寄出了，在路上。
- 「部分到手／全部到手」由收貨紀錄自動判斷，不能手動點。
- 修改進度會留下稽核紀錄。

## 預設台幣

新的供應商、新的採購團與品項都預設台幣；供應商設為日幣時，那一家才用日幣與匯率。
