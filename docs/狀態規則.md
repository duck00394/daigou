# 狀態規則

付款、訂單、採購／到貨、出貨分成四條獨立的軸，彼此不會互相觸發。例如付清款項不會變成已出貨，全部到貨也不會讓訂單完成。

## 人為設定與系統推算

| 項目 | 人為設定的欄位 | 系統推算 |
|---|---|---|
| 訂單確認 | 待確認／已確認／已取消 | — |
| 採購 | 明細：待採購、已向供應商下單、缺貨、延期 | 部分到貨、已到貨、已取消（依數量） |
| 備貨 | 明細：待備貨、備貨中、已備妥 | 部分出貨、已出貨、已送達、已取消（依出貨單） |
| 付款 | — | 全部依付款與退款紀錄推算 |

## 明細採購／到貨狀態
1. 有效件數 = 0 → 已取消
2. 已保留 + 已出貨 ≥ 有效件數 → 已到貨
3. 已保留 + 已出貨 > 0 → 部分到貨
4. 否則 → 人為設定值（待採購／已向供應商下單／缺貨／延期）

## 明細出貨狀態
1. 有效件數 = 0 → 已取消
2. 已出貨 ≥ 有效件數 → 已出貨（所屬出貨單都標記送達時為已送達）
3. 已出貨 > 0 → 部分出貨
4. 否則依備貨旗標：已備妥 → 待出貨、備貨中 → 備貨中、其他 → 待備貨

## 付款狀態（依序判斷）
1. 有待退款 → 退款處理中
2. 有已退款：淨收 ≤ 0 → 已退款；否則 → 部分退款
3. 已收 = 0 → 未付款（應收為 0 的有效訂單視為已付款）
4. 淨收 ≥ 應收 → 已付款
5. 否則 → 部分付款

## 訂單狀態（依序判斷）
1. 確認狀態為已取消，或所有明細都已全數取消 → 已取消
2. 待確認 → 待確認
3. 全部有效商品已出貨，且待收、應退、退款處理中都是 0 → 已完成
4. 有任何出貨 → 部分完成
5. 有任何到貨（含部分） → 處理中
6. 全部有效明細都已向供應商下單或已到貨 → 已下單
7. 淨收 < 應收 → 待付款
8. 否則 → 已確認

## 取消
- 只能取消「有效件數 − 已出貨」的數量，可以分多次取消；每次都留下取消紀錄（日期、數量、原因）與買家的客觀交易紀錄。
- 整單取消 = 取消所有未出貨的數量；若完全沒有出貨，訂單確認狀態改為已取消。
- 取消不會自動退款；若已收超過應收，系統顯示「應退」，需建立退款紀錄（待退款 → 已退款）。

## 追加
- 追加到原訂單：新增明細並標記「追加」，原明細不變；已取消或已完成的訂單不能追加。
- 獨立追加訂單：建立新訂單並連結原訂單，必須是同一買家、同一代購團。
- 匯入時不同代購團的資料不會被合併到同一張訂單。

## 匯入列狀態
| 狀態 | 意義 | 會建立訂單嗎 |
|---|---|---|
| 待確認 | 買家或商品未確定、內容無法判斷 | 否 |
| 錯誤 | 數量、金額、日期無效，或來源訂單編號已匯入過 | 否 |
| 可能重複 | 內容與既有訂單相同或相近 | 使用者勾選「仍要建立」後才會 |
| 已排除 | 使用者排除 | 否 |
| 可建立 | 已確認 | 是 |
| 已建立 | 已寫入正式訂單 | 不會重複建立 |
| 建立失敗 | 建立時發生錯誤 | 修正後可重試 |
