# 備份與還原

## 方式一：APP 內的完整備份（建議）
- 「匯出、備份與設定」→「下載完整備份」會下載一個 JSON 檔，包含所有業務資料表（商品、分類、代購團、買家、別名、標籤、訂單、明細、取消、付款、退款、採購批次、成本分攤、費用、庫存流水、出貨、匯入紀錄、稽核紀錄、設定與流水號）。不包含登入工作階段與登入失敗紀錄。
- 備份在同一個資料庫交易（REPEATABLE READ）中讀取，所有資料表來自同一個時間點。
- 檔案含檢查碼與每個資料表的筆數；還原前會先驗證，檔案被修改或損毀會拒絕。
- 還原：
  - 空的資料庫：直接還原。
  - 已有資料：必須勾選並輸入「清空後還原」，會先刪除目前所有業務資料再寫入備份。
  - 全部在單一交易中完成，任何一筆失敗就全部取消，不會留下一半的資料；完成後逐表核對筆數。
- 備份檔含買家私人資料，請存放在安全的位置（例如加密的雲端硬碟），不要上傳到公開的地方。
- 部署在 Vercel 時，單次上傳有大小限制（約 4.5 MB）。資料量大時請改用方式二還原。

## 方式二：PostgreSQL 標準工具
本系統使用標準 PostgreSQL，沒有特殊格式，可以用 pg_dump / pg_restore 在任何 PostgreSQL 主機之間搬移（本機、Neon、Supabase、自有 VPS）。

```bash
# 備份（自訂格式，可選擇性還原）
pg_dump "$DATABASE_URL" -Fc -f daigou-$(date +%Y%m%d).dump
# 或用專案指令（會讀取 .env 的 DATABASE_URL，檔案放在 backups/）
npm run backup:db

# 還原到新的空資料庫
pg_restore --no-owner --no-privileges -d "$NEW_DATABASE_URL" daigou-20261015.dump
```

搬家到新主機的步驟：
1. 在新主機建立空的 PostgreSQL 資料庫。
2. 用 pg_dump 備份舊資料庫，再 pg_restore 到新資料庫（或用 APP 的 JSON 備份：先對新資料庫執行 `npm run db:migrate`，登入後在設定頁還原）。
3. 把 `DATABASE_URL` 改成新主機，重新啟動。

## 建議的備份頻率
- 每次大量匯入或批次操作前，先下載一次完整備份。
- 平常至少每週一次；使用雲端免費資料庫時，不要只依賴平台本身的備份。
